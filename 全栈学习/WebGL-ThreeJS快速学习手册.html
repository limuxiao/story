WebGL 与 Three.js 快速学习手册

这份文档的目标是：用最短路径建立 3D Web 开发的底层心智模型。先理解 WebGL 在做什么，再看 Three.js 如何把它封装成场景、相机、网格、材质和动画。

适合：前端 / 全栈开发者 建议周期：7 天 形式：概念 + 对照 + 练习 项目案例：shipyard-fps
目录 心智模型 7 天路线 WebGL 底层 Three.js 封装 逐项对照 项目案例 练习任务 调试清单 速查表
一句话总览： WebGL 是“手动告诉 GPU 怎么画”；Three.js 是“用对象描述场景，由引擎翻译成 WebGL”。你学 Three.js 时，如果理解它背后对应的 WebGL 步骤，进步会快很多。

一、先建立心智模型

不管用原生 WebGL 还是 Three.js，最终流程都一样：把几何数据送到 GPU，用着色器计算顶点位置和像素颜色，然后输出到一个 canvas 上。

1. 几何数据顶点、法线、UV、索引
→
2. 变换矩阵模型、视图、投影
→
3. 着色器顶点 shader + 片元 shader
→
4. 光栅化三角形变像素
→
5. 输出画面framebuffer / canvas

原生 WebGL 关注什么

  • 怎么创建 context
  • 怎么编译 shader
  • 怎么上传 buffer
  • 怎么设置 attribute / uniform
  • 怎么调用 drawArrays / drawElements
  • 怎么管理 depth / blend / cull 等状态

Three.js 关注什么

  • Scene 里放什么对象
  • Camera 放在哪里、看向哪里
  • Mesh 用什么 Geometry 和 Material
  • Light / Fog / Shadow 怎么配置
  • 动画怎么播放
  • 交互怎么通过 Raycaster 检测
关键理解： Three.js 没有绕开 WebGL，它只是把 WebGL 的低层命令组织成了对象系统。调用 renderer.render(scene, camera) 时，Three.js 内部仍然在做 buffer 绑定、shader 选择、uniform 上传和 draw call。

三、原生 WebGL 是怎么工作的

1. 最小代码骨架

const canvas = document.querySelector('#gl');
const gl = canvas.getContext('webgl');

function compile(type, source) {
  const shader = gl.createShader(type);
  gl.shaderSource(shader, source);
  gl.compileShader(shader);
  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    throw new Error(gl.getShaderInfoLog(shader));
  }
  return shader;
}

function createProgram(vsSource, fsSource) {
  const program = gl.createProgram();
  gl.attachShader(program, compile(gl.VERTEX_SHADER, vsSource));
  gl.attachShader(program, compile(gl.FRAGMENT_SHADER, fsSource));
  gl.linkProgram(program);
  return program;
}

2. 顶点着色器负责“位置”

attribute vec2 aPosition;

uniform mat4 uProjection;
uniform mat4 uView;
uniform mat4 uModel;

void main() {
  gl_Position = uProjection * uView * uModel * vec4(aPosition, 0.0, 1.0);
}

3. 片元着色器负责“颜色”

precision mediump float;

void main() {
  gl_FragColor = vec4(1.0, 0.55, 0.2, 1.0);
}

4. 数据上传和绘制

const vertices = new Float32Array([
  -0.6, -0.4,
   0.6, -0.4,
   0.0,  0.6,
]);

const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.STATIC_DRAW);

const loc = gl.getAttribLocation(program, 'aPosition');
gl.enableVertexAttribArray(loc);
gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);

gl.useProgram(program);
gl.drawArrays(gl.TRIANGLES, 0, 3);
新手最容易卡住的地方： shader 编译失败、attribute location 没启用、矩阵顺序写反、忘记开深度测试、顶点绕序和面剔除冲突、canvas 尺寸和视口尺寸不一致。

5. 原生 WebGL 的开发顺序

  1. 创建 canvas 和 WebGL context。
  2. 编写顶点着色器和片元着色器。
  3. 准备顶点数据、索引、颜色、UV。
  4. 把数据上传成 buffer。
  5. 计算模型、视图、投影矩阵。
  6. 设置 uniform 和 attribute。
  7. 调用 drawArrays 或 drawElements。
  8. 用 requestAnimationFrame 重复执行。

四、Three.js 如何封装这些步骤

Three.js 的核心价值是把“命令式 GPU 调用”变成“声明式场景描述”。你不再直接管理 buffer 和 shader program，而是创建 Scene、Camera、Mesh、Material、Light 等对象。

1. 最小 Three.js 场景

const renderer = new THREE.WebGLRenderer({ canvas, antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);

const scene = new THREE.Scene();
scene.background = new THREE.Color(0x202830);

const camera = new THREE.PerspectiveCamera(
  70,
  window.innerWidth / window.innerHeight,
  0.1,
  100
);
camera.position.z = 5;

const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshStandardMaterial({ color: 0xff8844 });
const cube = new THREE.Mesh(geometry, material);
scene.add(cube);

const light = new THREE.DirectionalLight(0xffffff, 2);
light.position.set(3, 5, 4);
scene.add(light);

function loop() {
  cube.rotation.y += 0.01;
  renderer.render(scene, camera);
  requestAnimationFrame(loop);
}
loop();

2. renderer.render 内部做了什么

renderer.render(scene, camera)

  1. scene.updateMatrixWorld()
  2. camera.updateMatrixWorld()
  3. 计算 projection × view，生成视锥
  4. 遍历 Scene 树：projectObject()
  5. 过滤 visible、layers、frustumCulled
  6. 收集灯光、阴影、可渲染对象
  7. 对不透明/透明对象排序
  8. 为每个对象选择或生成 shader program
  9. 绑定 geometry / material / texture
 10. 上传 uniform
 11. 调用底层 drawArrays / drawElements
学习建议： 不要把 Three.js 当成完全不同的东西。每学一个 Three.js 类，都反向问：它替代了原生 WebGL 的哪段代码？例如 BufferGeometry 替代手写 buffer，Material 替代手写 shader uniform，Object3D 替代手写矩阵层级。

五、WebGL 与 Three.js 逐项对照

原生 WebGL Three.js 说明
getContext('webgl') WebGLRenderer 渲染器内部创建和管理 WebGL context。
手写向量、矩阵 Vector3 / Matrix4 / Quaternion Three.js 提供完整数学库。
persp() PerspectiveCamera 相机自动维护 projectionMatrix。
lookAt() camera.lookAt() 自动生成视图方向。
createBuffer() BufferGeometry 几何数据容器，内部再转成 WebGL buffer。
vertexAttribPointer() BufferAttribute + 渲染器内部绑定 无需手动设置 stride/offset。
compileShader() Material / ShaderMaterial 内置材质自动生成 shader，也可自定义 GLSL。
uniformMatrix4fv() 材质属性 / 渲染器内部 uniform 上传 例如 material.color、mesh.matrixWorld。
手写物体数组 Scene / Object3D 自动维护父子关系和世界矩阵。
手动排序和剔除 WebGLRenderLists + Frustum 自动视锥剔除、透明排序。
手写射线求交 Raycaster 鼠标拾取、射击检测更方便。
手写模型动画 AnimationMixer 播放 glTF / GLB 中的 AnimationClip。

六、结合当前项目理解

原生版 shipyard-fps.html

这是手写 WebGL 管理版：

  • canvas.getContext('webgl') 创建上下文
  • 自己写 persp()、lookAt()、trs()
  • 自己编译 mainProg、waterProg、skyProg
  • 自己把立方体顶点塞进数组并上传 buffer
  • 自己写雾、手电、水面波纹 shader
  • 自己在 render 里按天空、世界、水、敌人、枪械顺序绘制

Three.js 版 shipyard-fps-three.html

这是对象封装版：

  • WebGLRenderer 管理 GPU 渲染
  • Scene 管理场景树
  • PerspectiveCamera 管理相机
  • Mesh = Geometry + Material
  • FogExp2、SpotLight 管理氛围光
  • GLTFLoader 加载机器人，AnimationMixer 播放动画

Three.js 核心文件怎么看

当前项目的 fps/vendor/three.module.js 是 Three.js r160 核心包。它包含场景图、数学库、WebGLRenderer、材质、灯光、动画、射线检测和大量内置几何体。

注意：GLTFLoader、SkeletonUtils 这类扩展不在核心文件里，而在 vendor/addons/ 下。

版本意识： Three.js API 变化较快。学习时要先确认版本。当前项目是 r160，使用的是 outputColorSpace、SRGBColorSpace 这类较新的色彩管理 API。

八、调试清单

WebGL 黑屏排查

  • context 是否创建成功？
  • shader 是否编译成功？查看 gl.getShaderInfoLog。
  • program 是否 link 成功？查看 gl.getProgramInfoLog。
  • attribute location 是否有效？是否 enableVertexAttribArray？
  • vertexAttribPointer 的 size、stride、offset 是否正确？
  • uniform location 是否为 null？
  • 矩阵乘法顺序是否正确？
  • 是否设置了 viewport？
  • 是否 clear 了 color/depth buffer？
  • 物体是否在视锥内？

Three.js 物体看不见排查

  • 是否 scene.add(object)？
  • object.visible 是否为 true？
  • position / scale 是否异常？
  • 几何体包围盒是否正确？
  • frustumCulled 是否误剔除？
  • 材质 side 是否朝向正确？
  • 是否需要灯光？MeshBasicMaterial 不需要，Standard 需要。
  • 透明度、深度写入、renderOrder 是否冲突？
  • 模型缩放是否按真实几何尺寸计算？骨骼模型尤其要注意。

性能优化清单

  • 减少 draw call：合并静态几何体。
  • 重复物体使用 InstancedMesh。
  • 减少材质种类和 program 切换。
  • 纹理使用压缩格式。
  • 启用视锥剔除。
  • 阴影贴图尺寸不要盲目过大。
  • 粒子系统用 Points 或实例化，不要大量 Mesh。
  • 删除对象时调用 geometry.dispose() / material.dispose() / texture.dispose()。
常见问题：为什么机器人模型加载了却看不见？

常见原因是缩放计算错误。骨骼模型用 Box3.setFromObject() 时可能把骨骼层级也算进去，导致 scale 极小。更稳妥的做法是只遍历真实 Mesh，用每个 geometry 的 boundingBox 乘以 matrixWorld 后合并包围盒。

常见问题：Three.js 为什么还要自己写 requestAnimationFrame？

Three.js 的 renderer 只负责“渲染一帧”，游戏循环仍然由你控制。你也可以用 renderer.setAnimationLoop()，它在 XR 场景里更方便，但普通项目里手写 rAF 更直观。

最后建议

最有效的学习顺序不是“先啃完 Three.js 所有 API”，而是：先用原生 WebGL 画一个三角形，理解 GPU 管线；再用 Three.js 重写同一个场景；然后逐步加相机、光照、模型、动画和交互。每加一个功能，都思考它背后的 WebGL 步骤。

如果你要做游戏，真正难的部分通常不是 WebGL API，而是：坐标系统、矩阵、碰撞、状态管理、资源生命周期、性能预算和调试能力。
