1. 渲染管线总览

WebGL 的渲染管线主干可以概括为：

顶点数据（CPU 缓冲区）
    ↓
顶点着色器（可编程，逐顶点）
    ↓
图元装配 + 光栅化（固定功能）
    ↓
片段着色器（可编程，逐片段/像素）
    ↓
逐片段操作（深度测试、混合等，固定功能）
    ↓
帧缓冲区 → 屏幕
关键认知：开发者主要编写的是顶点着色器和片段着色器，以及 CPU 端的 JavaScript 数据准备。光栅化是 GPU 固定功能，开发者无法编程其逻辑，只能通过图元类型、viewport 等 API 间接影响。

WebGL 程序的基本结构遵循两阶段模式[citation:3][citation:10]：

  • 初始化阶段：创建着色器和程序、查找 location、创建缓冲区、上传顶点数据
  • 渲染阶段：清屏、设置全局状态 → 对每个物体：设置属性、设置 uniform、调用 drawArrays / drawElements

2. 着色器变量：attribute / uniform / varying

GLSL 中有三种核心变量限定符，各自用途完全不同[citation:2]：

限定符 可用着色器 数据粒度 典型用途 WebGL 设置方式
attribute 仅顶点着色器 每个顶点一份 位置、法线、UV、顶点色 vertexAttribPointer
uniform 顶点 & 片段 每次绘制共享一份 变换矩阵、时间、光照参数 uniformMatrix4fv 等
varying 顶点→片段（单向） 顶点写入，光栅化插值 渐变坐标、纹理坐标、法线 两边同名声明即可

核心理解

  • attribute：逐顶点数据，必须来自缓冲区，通过 getAttribLocation 获取整数索引。
  • uniform：全局共享，通过 getUniformLocation 获取不透明对象。如果着色器声明了但未实际使用，会被优化掉，查询返回 null。
  • varying：不是“共用变量”，而是顶点着色器写入 → 光栅化插值 → 片段着色器读取的单向管道。两边必须同名同类型。

3. 顶点着色器与片段着色器

顶点着色器：逐顶点执行

核心任务是计算 gl_Position，并可通过 varying 向片段着色器传递插值数据：

attribute vec2 aPosition;
uniform mat4 uProjection, uView, uModel;
varying vec2 vPosition;

void main() {
    vPosition = aPosition;
    gl_Position = uProjection * uView * uModel * vec4(aPosition, 0.0, 1.0);
}

片段着色器：逐片段执行

核心任务是计算 gl_FragColor（WebGL 1），决定像素颜色：

precision mediump float;
uniform vec3 uColor;
varying vec2 vPosition;

void main() {
    float t = vPosition.x * 0.5 + 0.5;  // 映射到 [0,1]
    gl_FragColor = vec4(uColor * (0.3 + 0.7 * t), 1.0);
}

片段着色器不仅能“设颜色”，还能做纹理采样、光照计算、程序化图案、discard 丢弃片段等，但它不能改变图元形状——三角形覆盖哪些像素是光栅化决定的[citation:13]。

4. 光栅化与片段

光栅化是 GPU 固定功能阶段，负责两件事：

  1. 确定三角形覆盖了哪些像素网格位置
  2. 对 varying 变量在三角形内部进行插值
片段 ≠ 最终像素。光栅化生成的“片段”是候选像素，要经过深度测试、模板测试、混合等逐片段操作，通过测试的才写入帧缓冲区成为最终像素。片段着色器的执行次数 = 生成的片段数，而非最终可见像素数。

默认情况下，一个片段对应一个像素网格位置。多重采样（MSAA）和可变速率着色（VRS）等技术会改变这种对应关系，但不是 WebGL 的默认行为。

5. 缓冲区与绘制调用

顶点数据通过缓冲区上传到 GPU：

const vertices = new Float32Array([...]);
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.STATIC_DRAW);

告诉 GPU 如何解读数据：

gl.enableVertexAttribArray(loc.position);
gl.vertexAttribPointer(loc.position, 2, gl.FLOAT, false, 0, 0);

图元类型决定了顶点如何组装：

mode规则典型用途
gl.TRIANGLES每 3 个顶点一个独立三角形通用、矩形拆两三角形
gl.TRIANGLE_STRIP相邻三角形共享边条带表面、省顶点
gl.TRIANGLE_FAN共享第一个顶点呈扇形圆形/锥体
gl.LINE_STRIP顶点依次相连折线、曲线

WebGL 没有矩形图元，矩形必须用两个三角形（gl.TRIANGLES）或 TRIANGLE_STRIP 实现。

6. MVP 矩阵：uModel / uView / uProjection

这是 WebGL 3D 渲染的核心概念[citation:4]：

局部坐标 ─×uModel→ 世界坐标 ─×uView→ 相机坐标 ─×uProjection→ 裁剪空间
矩阵作用变化频率谁不同
uModel 物体自身的平移/旋转/缩放 每帧（物体动） 每个物体不同
uView 相机位置/朝向（世界→相机） 相机移动时（FPS 几乎每帧） 整个场景共享
uProjection 投影方式（相机→裁剪） resize / FOV 变化时 整个场景共享
单位矩阵的含义：如果 uProjection 传单位矩阵，等价于“不做投影变换”，顶点直接当 NDC 坐标用，可见范围 [-1,1]。这是简化 2D 示例的常见做法，正式 3D 项目不会这么做。

7. 多物体绘制

不需要为每个物体写着色器。通常一类渲染逻辑共用一个 program，通过每次 draw call 前设置不同的 uModel 和绑定各自的缓冲区来区分物体[citation:10]。

典型的渲染循环：

gl.useProgram(program);           // 若程序不变，一次即可
// 设置全局 uniform（projection、view、time）
for (const obj of objects) {
    gl.uniformMatrix4fv(loc.model, false, obj.modelMatrix);
    gl.bindBuffer(gl.ARRAY_BUFFER, obj.buffer);
    gl.vertexAttribPointer(...);
    gl.drawArrays(gl.TRIANGLES, 0, obj.count);
}

只有渲染逻辑本质不同（如 3D 光照 vs 后处理）才需要多个 program。大量相同几何的物体可用 instancing（drawArraysInstanced）合并 draw call。

CPU 与 GPU 的分工：CPU 每帧计算游戏逻辑、碰撞检测、每个物体的变换矩阵；GPU 顶点着色器用矩阵并行变换顶点，片段着色器上色。CPU 不逐顶点计算位置（除非特殊场景如 CPU 蒙皮）。

8. 透视投影与近大远小

近大远小的效果来自透视投影矩阵。其核心机制是：矩阵让输出的 w 分量等于相机空间的深度，GPU 自动做透视除法（x、y、z 除以 w），远处物体 w 更大，xy 被除得更小，投影到屏幕上就更小[citation:5]。

function perspective(fovy, aspect, near, far) {
    const f = 1 / Math.tan(fovy / 2);
    const nf = 1 / (near - far);
    return new Float32Array([
        f / aspect, 0, 0, 0,
        0, f, 0, 0,
        0, 0, (far + near) * nf, -1,   // 关键：-1 让 w = -z
        0, 0, 2 * far * near * nf, 0,
    ]);
}

玩家跑动时不调整 uProjection，而是调整 uView（相机位置变）。透视矩阵作为“规则”缓存复用，只有 FOV 变（开镜）、宽高比变（resize）、裁剪面变时才重算。

配套设置：3D 场景需要 gl.enable(gl.DEPTH_TEST) 并每帧清深度缓冲 gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT)。
